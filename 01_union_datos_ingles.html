2 Source 1: census tract → neighbourhood bridge table

Dataset comments:

This block builds the relationship between census tracts and neighbourhoods. The neighbourhood is a stable unit of analysis for the whole study period except for three known exceptions dated in 2017 (see Note). Census tracts, on the other hand, are not stable over time, so a fixed crosswalk loses a growing fraction of population the further away the crosswalk’s reference date is from 2024 (empirically checked against composición_hogares/ 2017-2025).

Note: 2017 has 128 neighbourhoods, not 131: Ensanche de Vallecas, Valderrivas and El Cañaveral did not exist as neighbourhoods of their own as of January 1st, 2017 - their census tracts belonged to Villa de Vallecas/Vicálvaro.

2.1.1 Source 1a: neighbourhood names (seccion_censal_barrio_correspondencia.xls)

seccion_censal_barrio_correspondencia.xls is used only to obtain district/neighbourhood names (not to build the tract-neighbourhood relationship, since it has two transcription omissions: tracts 10220 and 16137)

nbsp <- " " # Stores in a variable the NBSP character (non-breaking space) since many cells carry it by default.

raw_corr <-
  read_excel("../data/raw/seccion_censal_barrio_correspondencia.xls", sheet = 1,
             col_names = FALSE) %>% # marks that the first column is data, not a header
  rename(etiqueta = ...1) %>% # renames that first column ...1 to "etiqueta".
  mutate(
      etiqueta = str_squish(str_replace_all(etiqueta, nbsp, " ")),
      # str_replace_all replaces every NBSP with a normal space and str_squish trims spaces and collapses multiple internal spaces into one.

      # main difference: district row: "01. CENTRO" (period + space); neighbourhood row: "01.1 Palacio" (period + digit)
      es_distrito = str_detect(etiqueta, "^\\d{2}\\.\\s"),
      es_barrio   = str_detect(etiqueta, "^\\d{2}\\.\\d+\\s"))

distritos <- raw_corr %>%
  filter(es_distrito) %>% 
  transmute( 
    distrito_num = as.integer(str_extract(etiqueta, "^\\d{2}")), # extracts the first two digits and converts them to integer (drops the leading zero, e.g. "01" → 1).
    distrito_nombre = str_remove(etiqueta, "^\\d{2}\\.\\s*") %>% # Removes the "01. " prefix (digits, period, spaces).
      str_replace_all("\\s*\\.\\s*", "-") %>% # turns " . " into a hyphen
      str_to_title() %>% # converts to title case (initial capital on each word): "San Blas-Canillejas".
      str_replace_all("\\bDe\\b", "de") # Since str_to_title() also capitalizes prepositions like "de", this lowercases them again, giving "de la Concepción".
  )

barrios_madrid <- raw_corr %>%
  filter(es_barrio) %>%
  transmute(
    distrito_num = as.integer(str_extract(etiqueta, "^\\d{2}")), 
    barrio_num   = as.integer(str_extract(etiqueta, "(?<=^\\d{2}\\.)\\d+")), # uses a lookbehind (?<=^\\d{2}\\.)\\d+ — extracts the digits that come right after "two digits + period" at the start, without including those two digits or the period in the result.
    barrio_nombre = str_trim(str_remove(etiqueta, "^\\d{2}\\.\\d+\\s*")), # removes the "01.1 " prefix and trims leftover spaces
    barrio_oficial = distrito_num*10 + barrio_num, # building the neighbourhood-district code as it appears in some files
    codigo_barrio = sprintf("%02d%d", distrito_num, barrio_num) # building the neighbourhood-district code as it appears in other  files = DDB format (2-digit district + neighbourhood without zeros), e.g. "014" = Justicia
  ) %>%
  left_join(distritos, by = "distrito_num") %>% # for each row of the neighbourhood table, looks up in distritos the row with the same distrito_num.
  select(distrito_num, distrito_nombre, barrio_num, barrio_nombre, codigo_barrio, barrio_oficial) %>%
  arrange(distrito_num, barrio_num)

2.1.3 Neighbourhood-tract at a reference date

# Used to answer "given a census tract code, which neighbourhood did it belong to on a specific date?"
crosswalk_a_fecha <- function(historia, fecha_ref) {
  historia %>%

    filter(fecha_alta <= fecha_ref) %>% # keeps only the tracts that already existed at fecha_ref, whose registration date is earlier than the reference date...
    filter(is.na(fecha_baja) | fecha_baja > fecha_ref) %>% # ...and that have not been deregistered (either no deregistration date, OR a deregistration date later than the reference date).

    mutate(
      barrio_oficial = if_else( # determines which neighbourhood each tract belonged to at each fecha_ref
        !is.na(fecha_modificacion) & !is.na(barrio_antiguo) & fecha_ref < fecha_modificacion,
        # if this tract did have a registered neighbourhood change (fecha_modificacion AND barrio_antiguo are not empty), AND the reference date being queried is earlier than when that change happened...
        barrio_antiguo, # TRUE: the change had not happened yet (date earlier than fecha_ref) = returns the previous neighbourhood (from the barrio_antiguo column).
        barrio_registrado  # FALSE: the change has already happened (date later than fecha_ref) = returns the current neighbourhood (from the barrio_registrado column).
    )) %>%
    transmute(distrito, seccion, barrio_oficial)
}

parse_num <- function(x) {
  x <- as.character(x) # converts x (the column vector) to text so transformations can be applied, then stores it as numeric.
  x <- if_else(x == "..", NA_character_, x) # wherever ".." appears writes NA, and keeps the values of x everywhere else
  x <- str_remove_all(x, "\\.") # removes the thousands-separator periods
  as.numeric(x)
}

leer_composicion_anio <- function(anio) { # Defines a function that takes a year (anio) and returns that year's household composition data 

  archivo <- list.files("../data/raw/composición_hogares",
                        pattern = paste0("^", anio, "_hogares\\.xlsx?$"), full.names = TRUE) # Looks within the folder for the file whose name exactly matches the pattern: year followed by _hogares.xlsx or _hogares.xls.
             stopifnot(length(archivo) == 1) # warns if more than one file matches that pattern, or none


  hojas <- excel_sheets(archivo) # lists the names of every sheet that excel file has
  hoja_comp <- hojas[str_detect(str_to_lower(hojas), "composici")] # looks for the one with "composici" in lowercase (saves having to match the accent).
  stopifnot(length(hoja_comp) == 1) # warns if more than one sheet matches that pattern, or none


  raw <- read_excel(archivo, sheet = hoja_comp, col_names = FALSE) # reads the composition sheet, without assuming a header row
  cabecera_limpia <- str_to_lower(str_squish(coalesce(as.character(raw[6, ]), as.character(raw[5, ])))) # extracts row 6 (or failing that row 5) in full (where the column names are), converts it to lowercase text and applies str_squish to clean up spaces - the result is a text vector in order.
  objetivo_limpio <- str_to_lower(str_squish(columnas_objetivo))


  idx <- match(objetivo_limpio, cabecera_limpia)
  names(idx) <- columnas_objetivo # assigns the original name to each of the 9 numbers in the idx vector - in order.

 if (any(is.na(idx))) { # checks whether there is at least one TRUE in the vector generated by is.na(idx)
  stop(sprintf("Year %d: there is a column-matching error: %s",
               anio, paste(columnas_objetivo[is.na(idx)], collapse = "; "))) 
 }

  col_seccion <- str_squish(as.character(raw[[2]])) # col2 = tract code
  es_seccion <- replace_na(str_detect(col_seccion, "^\\d{5}$"), FALSE) # str_detect identifies the rows that are a census tract, discarding header, total or empty rows - the result is a TRUE/FALSE/NA vector. replace_na(..., FALSE) replaces any NA that might come out (if some cell was empty) with FALSE - the result is a TRUE/FALSE vector.

  valores[[nombres_finales[i]]] <- parse_num(datos[[idx[i]]]) # datos[idx[i]] extracts from "datos" the excel column position corresponding to category number i, cleans it with the parse_num defined earlier, and stores it inside valores under the name corresponding to position i of nombres_finales.
}

  bind_cols(tibble(codigo_seccion = codigo_seccion), valores) %>% mutate(anio = anio) # joins the tract-code table and the values table - one table next to the other - adding the year (anio) column.
}

Dataset comments:

The variables extracted are: average rent for multi-family housing, average rent for single-family housing, number of multi-family housing units, and number of single-family housing units. 4.1.3 (Weighted) aggregation to neighbourhood level

To summarize several tracts into a single neighbourhood figure, the chosen approach was to compute the weighted mean of the tract-level medians, which gives each tract a “weight” proportional to its size (the number of dwellings). Since individual dwelling-level data is not available to extract their median directly, this measure was chosen to approximate it.

# Defines the function, with x (the values, the rent medians per tract) and w (the weights, the number of dwellings per tract)

weighted_mean_safe <- function(x, w) {
  # checks to make it robust (safe)
  valido <- !is.na(x) & !is.na(w) & w > 0 # the value cannot be missing & the weight cannot be missing & weight > 0
  if (!any(valido)) return(NA_real_) # if no tract of the neighbourhood is usable returns NA // if at least one is valid, applies the following weighted-mean operation to them:
  sum(x[valido] * w[valido]) / sum(w[valido]) # MEAN: multiplies the value by its weight, sums everything and divides by the sum of the weights.
}

# defines a name-normalization function

normalizar_nombre <- function(x) {
  x %>%
    stringi::stri_trans_general("Latin-ASCII") %>% # removes accents/diaeresis/ñ -> n
    str_to_upper() %>% # converts everything to uppercase
    str_replace_all("[^A-Z0-9]+", " ") %>% # any character (or run of one or more) that is ^ NOT an uppercase letter (A-Z) nor a digit (0-9) is replaced with a space " ".
    str_squish() # cleans up leftover leading/trailing or duplicate spaces just in case
}

# looks at the first rows and columns of the sheet searching for the word "Superficie" (which tells it which column holds the indicator labels) and the word "CIUDAD" (which tells it which column the data block starts in and which row the header with neighbourhood names is on) -> this can't be done with fixed positions since it varies by edition

localizar_columnas_panel <- function(raw) {

  texto <- apply(esquina, c(1, 2), function(v) if (is.na(v)) NA_character_ else str_squish(as.character(v))) # each cell (1,2) of esquina stays NA text if it is NA, and otherwise is converted to text/has its spaces cleaned.

9.1.2 Numeric parsing, column-pair extraction and row location

Both functions are defined to solve problem a and problem b:

  1. Within the same edition some district sheets store numbers as text in European format and others as native Excel numbers. Also, a single period is ambiguous on its own (e.g.: “1.114”), so it is resolved by knowing in advance whether the indicator is a count (thousands separator) or a rate/proportion (decimal), the type defined in specs_panel.

  2. Each geography (City/District/Neighbourhood) occupies a pair of contiguous columns, but what each of those two columns represents depends on the indicator. Depending on the mode (which reflects the indicator’s statistical meaning, decided in advance, in specs_panel) it is decided how to extract it. Position rule common to all three modes: if only one column has content, that is the value that will be used, whether A or B, using the determined mode.

  • mode = “simple”, type = “proporcion”: the indicator can only be a rate. The value may be in A or in B depending on the edition, and whichever has content is used (priority B, then A). -> Density, Average age, Household size, aging, over-aging, migrants, unemployment.

  • mode = “simple”, type = “conteo”: the indicator is indeed an actual count. It is normally in the 2nd column (B); the 1st (A), if it exists, is the % over the overall geography (not comparable across neighbourhoods) and is ignored without being read - unless B is empty, in which case it becomes the value to use. -> Total population, Number of households, single-parent households.

  • mode = “dual”: both columns are useful and are read independently. 1st (A) = % over the geography itself and 2nd (B) = absolute count. If one is missing, only that one is left NA, without affecting the other. -> Spanish/foreign nationality, education level.

Risk accepted in this extraction logic: The pipeline decides that if both have content, the 2nd is the useful value and the 1st is discarded. This rule is based on an empirical check, both manual and through iterations with Claude Code, however there is a risk that in some specific case the values are reversed.

# solution to problem a.
# type="proporcion": a period (without a comma) is a decimal and is not removed.
# type="conteo": a period followed by groups of exactly 3 digits IS a thousands separator and IS removed.

parse_num_panel <- function(x, tipo = c("conteo", "proporcion")) { # the types can be conteo or proporcion
  tipo <- match.arg(tipo) # match.arg() checks that tipo is one of those two

  if (is.numeric(x)) return(as.numeric(x)) # if the cell already came as a native Excel number, it stays as is
  x <- as.character(x) # if it wasn't numeric it is converted to text
  if (is.na(x) || x == "") return(NA_real_) # and if it is empty or NA it becomes NA_real_


  # CASE 1: if the text contains a comma it is assumed to be European notation and then...
  if (str_detect(x, ",")) {
    x <- str_remove_all(x, "\\.") # all periods are removed from the text (they are thousands separators)
    x <- str_replace(x, ",", ".") # replaces the comma with a period
    return(as.numeric(x)) # and converts to number
  }

  # CASE 2: if there's no comma but there is a period, it depends on the indicator's type
  if (tipo == "conteo" && str_detect(x, "^\\d{1,3}(\\.\\d{3})+$")) { # when the indicator's type is conteo AND the pattern matches groups of three digits separated by a period.
    return(as.numeric(str_remove_all(x, "\\."))) # the periods are removed from the text (they are thousands separators)
  }

  # CASE 3: if the type is "proporcion" + if it is text in normal format (123) + a count that doesn't match the three-digit pattern.
  as.numeric(x)
}


# solution to problem b.
valor_par_panel <- function(raw, fila, col_inicio, modo = c("simple", "dual"), tipo = NULL) {
  # col.inicio is the column where the A-B pair starts
  # fila is where the indicator is located (already found with localizar_fila_panel)
  modo <- match.arg(modo)

  # reads the two values of the A-B pair and with a_ok and b_ok recreates a boolean flag, indicating whether cell a and cell b have real content.
  a <- raw[[fila, col_inicio]]
  b <- raw[[fila, col_inicio + 1]]
  a_ok <- !is.na(a) && a != ""
  b_ok <- !is.na(b) && b != ""

  # CASE 1, simple: if it has content B is used, if that one is empty A will be used. The earlier parse is used.
  if (modo == "simple") {
    if (b_ok) return(list(valor = parse_num_panel(b, tipo)))
    if (a_ok) return(list(valor = parse_num_panel(a, tipo)))
    return(list(valor = NA_real_))
  }

  # CASE 2, dual: A and B are read completely independently
  list(
    proporcion = if (a_ok) parse_num_panel(a, "proporcion") else NA_real_,
    valor = if (b_ok) parse_num_panel(b, "conteo") else NA_real_
  )
}


# Locating the panel's rows, the indicators

localizar_fila_panel <- function(raw, label_col, patron, excluir = NULL) {
  etiquetas <- raw[[label_col]] # extracts the whole indicator-label column from raw
  etiquetas_sq <- ifelse(!is.na(etiquetas), str_squish(as.character(etiquetas)), NA_character_) # if there is a value it converts it to text and applies space cleanup, otherwise NA.

  match_incluir <- str_detect(etiquetas_sq, regex(patron, ignore_case = TRUE)) # returns a TRUE/FALSE vector indicating which labels to include if they match the pattern (anywhere in their text, case-insensitively).
  match_incluir[is.na(match_incluir)] <- FALSE # sets FALSE in the previous vector wherever it is NA.

  if (!is.null(excluir)) { # in case there is an exclusion pattern (same logic)
    match_excluir <- str_detect(etiquetas_sq, regex(excluir, ignore_case = TRUE))
    match_excluir[is.na(match_excluir)] <- FALSE

    match_incluir <- match_incluir & !match_excluir # labels matching the sought pattern AND not matching the discard pattern are included.
  }
  which(match_incluir) # returns the positional indices where the vector is TRUE.
}

# processes ONE indicator (one panel row) and returns the column(s) that correspond to it
# locates the row, checks that it is unique, extracts the value for each neighbourhood creating one column ("simple" mode) or two ("dual" mode)

procesar_indicador <- function(raw, cols, barrio_cols, nombre_col, spec, anio_edicion, hoja) {
  fila_ind <- localizar_fila_panel(raw, cols$label_col, spec$patron, spec$excluir) # looks up this indicator's row, using the inclusion pattern and the exclusion pattern.

  # checks that exactly one row was found, otherwise stops execution
  if (length(fila_ind) != 1) {
    stop(sprintf("Edition %d, sheet %s, indicator %s: %d rows found (1 expected)",
                  anio_edicion, hoja, nombre_col, length(fila_ind)))
  }

  # for each neighbourhood column extracts the value with valor_par_panel() using modo and tipo
  valores <- map(barrio_cols, ~ valor_par_panel(raw, fila_ind, .x, modo = spec$modo, tipo = spec$tipo))

  # Depending on the mode, generates the function's result: columnas (the variable names) and valores paired by position.
  if (spec$modo == "dual") {
    list(
      columnas = c(paste0(nombre_col, "_pct"), nombre_col),
      valores = list(map_dbl(valores, "proporcion"), map_dbl(valores, "valor")))
  } else {
    list(columnas = nombre_col, valores = list(map_dbl(valores, "valor")))
  }
}

  tabla_join <- tabla %>%
    mutate(distrito_key = normalizar_nombre(distrito_txt), barrio_key = normalizar_nombre(barrio_txt)) %>% # creates distrito_key and barrio_key columns by applying normalizar_nombre (created in source 6)

    left_join(
      barrios_madrid_norm_panel %>%
        select(distrito_key, barrio_key, distrito_num, distrito_nombre, barrio_num, barrio_nombre, codigo_barrio), by = c("distrito_key", "barrio_key")) # joins the table with barrios_madrid_norm_panel -> with already-normalized neighbourhood names.

  barrio_num <- id_num %% 100 # returns the neighbourhood
  sprintf("%02d%d", distrito_num, barrio_num) # rebuilds the codigo_barrio format
}

11 Source 10: residential churn (churn_total/)

Dataset comments:

These variables are built from 4 Banco de Datos files that record Padrón registrations and deregistrations. They are proxies for population turnover, resident inflow and outflow rates per neighbourhood-year. They are computed keeping the direction of the movement but collapsing 2 origins, giving 1) domestic registrations (altas) / deregistrations (bajas), internal to the city of Madrid, 2) residential registrations/deregistrations, external to the city. Dividing by the neighbourhood’s total population to compute the rates normalizes the absolute counts by population size, so they are comparable between large and small neighbourhoods.

parse_num_churn <- function(x) as.numeric(str_remove_all(x, "\\.")) # removes the thousands-separator period

leer_churn_archivo <- function(nombre_archivo) {
  archivo <- sprintf("../data/raw/churn_total/%s.xlsx", nombre_archivo)
  read_excel(archivo, sheet = 1, skip = 8, # sheet 1, skips 8 rows
             col_names = c("anio_txt", "distrito_txt", "barrio_txt", "total_txt", "espanola_txt", "extranjera_txt"), col_types = "text") %>% # forces them to be read as text

    filter(as.integer(anio_txt) <= 2023) %>% # filters years less than 2023
    filter(barrio_txt != distrito_txt) %>% # discards "Ciudad de Madrid" and the district-total rows by removing those rows that have the same text in both columns
    filter(str_detect(barrio_txt, "^\\d{3}\\.\\s")) %>% # only real neighbourhoods (3-digit pattern)
    filter(!str_detect(barrio_txt, regex("No consta", ignore_case = TRUE))) %>% # "000. No consta" does match the 3-digit pattern, so it is explicitly excluded

      anio = as.integer(anio_txt),

}

Dataset comments:

The variables extracted are investment budget and actual spending by district and the intensity of investment based on the budget and actual spending. The intensity is understood as the value divided by the district population. leer_zonas_verdes_significativas_anio <- function(anio) {
  archivo <- sprintf("../data/raw/zonas_verdes_distrito/zonas_verdes_%d.xlsx", anio)
  raw <- read_excel(archivo, sheet = "ZV Y PARQUES SIGNIFIC. DISTRITO")

  col_distrito <- names(raw)[str_detect(names(raw), "^DISTRITO$")] # looks for the column matching distrito
  col_ha <- names(raw)[str_detect(names(raw), regex("\\bha\\b", ignore_case = TRUE))] # looks for the column containing Ha: the surface area
  stopifnot(length(col_distrito) == 1, length(col_ha) == 1) # verifies that each search found one column

  raw %>% # table with two variables: district name and park hectares
    transmute(distrito_txt = .data[[col_distrito]],
              ha_parque = as.numeric(.data[[col_ha]])) %>%
    filter(!is.na(distrito_txt), !is.na(ha_parque)) %>% # keeps only the ones that do have values in both columns
    filter(!str_detect(distrito_txt, regex("total", ignore_case = TRUE))) %>% # removes total rows
    group_by(distrito_txt) %>% # groups by district... to sum all the hectares
    summarise(zonas_verdes_significativas_ha = sum(ha_parque), .groups = "drop") %>%
    mutate(anio = anio, .before = 1) # adds the year column
}

Dataset comments:

There are two files: estaciones_metro_nodes.csv (holds the stations with X/Y coordinates and their attributes), itinerarios_metro_edges.csv (holds the itineraries, the ordered sequence of stations and the distance to the previous station).

This variable is at neighbourhood level but has no year dimension since it is the current snapshot of the CRTM metro network. Using the current snapshot does not introduce much variation since the only modification completed and opened within the city of Madrid’s limits between 2017 and 2026 was the creation of the Arroyofresno station (Line 7) in 2019. In the raw data there is an error in the Arroyofresno station’s start date, which actually corresponds to April 2019, this being the only relevant metro-network modification. It will be accounted for through a manual correction in the years 2017 and 2018.

For every neighbourhood with a station of its own, the built variable represents the minimum number of segments (track segments between two consecutive stations of the same itinerary in a given direction) that must be traveled on the shortest path (measured in number of segments) from that station to Sol, treated as the reference “center” since it is kilometer zero of the Spanish radial highways. It is computed by building the metro network as a graph (stations = nodes; segments between consecutive stations = edges with weight 1 each, a transfer between lines at the same physical station = edge with weight 0, not counted as a traveled segment) and applying Dijkstra (via igraph::distances()) from Sol to the rest of the stations. There are 32 neighbourhoods that have no metro station of their own, so they are left with paradas_red_centro as NA.
